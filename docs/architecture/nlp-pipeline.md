# Web conversion pipeline

Time to Local parses messages locally in a disposable browser worker. The launch path uses pinned Chrono and bundled Temporal, without a model download or conversion service.

```mermaid
flowchart LR
    input[Editable message] --> worker[Cancellable worker]
    worker --> parse[Chrono and bounded extensions]
    parse --> context[Source date and range context]
    context --> zones[Offsets, regions, cities and ambiguity]
    zones --> temporal[Exact instants and DST alternatives]
    temporal --> merge[Stable result identity and duplicates]
    merge --> format[Target timezone and display preferences]
    format --> results[Date, time, zone and Copy]
```

## Parsing and source context

`engine/parser.ts` clones the pinned English Chrono parsers for month/day and day/month conventions. Bounded extensions handle military hours, shorthand meridiem and between-ranges. `convert.ts` receives the reference instant, default source zone, target zone and numeric-date order explicitly.

The reference day is resolved in the source zone. Date context may apply within a sentence/list and resets across unrelated text. Date/time merging rejects a sentence-ending period or an unrelated bare paragraph break before either can hide the original boundary; explicit `at`/`on` connectors and existing standalone date headings retain their behavior. A rejected preceding date cannot subsequently become implicit context for the clock. Ranges retain endpoint order and overnight dates. Inherited explicit range years remain explicit for disclosure; only reference-derived years can produce an assumed-year annotation. Dates without times remain dates; in messages containing clocks, standalone dates serve as context rather than extra result rows. Unix seconds use a bounded supported interval.

`engine/date-context.ts` prepares each original message before parsing. A complete month-name/day heading (either textual order, optional ordinal/year and consistent weekday) can own immediately following clock-first bullet or numbered items at the same indentation. Plain, trailing-colon, one-to-six-hash Markdown and bold headings qualify; one blank before the first item is allowed. Prose, a nonclock first item, a blank inside the list, changed indentation, another heading, competing dates, quotes or fences end ownership. An explicit event date overrides that event while later siblings retain their heading date.

A blank-delimited record can also supply context when it contains exactly one `Date` before exactly one `Time`, with case-insensitive labels and optional non-temporal `Title`, `Activity` or `Location` fields. Validation examines the whole block, so late duplicates, unknown fields, Time-first order and asserted temporal optional values decline association. Assertions include certain clock cores (including noon/midnight), genuine ranges, complete calendar dates, explicit month/year references, weekdays and parser-owned relative calendar/instant expressions. A month word with only an implied day/year or a vague period with only an implied hour may remain ordinary optional-field text. Location does not supply a timezone. Tables, numeric headings, raw HTML/YAML, bracketed date headings and general prose inference remain outside this extension.

Clock-first values may contain one native clock/range or two detected clocks joined by the existing qualified-zone range connector; additional independent assertions decline inherited ownership. Explicit double-hyphen clock sequences in lists retain separate points without overnight rollover. After a complete clock-first core, parser-confirmed vague Morning/afternoon/evening/night activity receives a barrier before native merging, including activity separated by a colon. Actual `in the morning/afternoon` and `at night` clock modifiers retain native meaning. A blank or indentation reset still ends date ownership while clock-first activity barriers keep vague title words from modifying an independent fallback clock. Complete dates, relative expressions and certain clocks in the remaining value stay authoritative. Dash followed by a noon/midnight-starting title with further text is unsafe for positive carry; a colon does not erase an ambiguous certain noon/midnight assertion. These constructions decline association without assigning a new point-only interpretation.

One shared scanner masks complete same-line Markdown destinations, including balanced parentheses, escaped delimiters, angle-enclosed URIs and quoted titles, and bare HTTP(S) URLs. Optional-field inspection and scoped extraction use the same opaque metadata spans, while visible labels retain their qualified temporal meaning. Within indexed domains, the metadata-only semantic copy supplies zone/offset lookup, Unix-seconds extraction and vague-term warnings. Clock reparsing uses the same prepared activity barriers as initial extraction so removed title interpretations cannot return. Displayed source text remains an exact slice of the original input; metadata is never fetched. A fence closes only with the same delimiter character, at least the opening length and whitespace-only trailing content.

Preparation replaces scoped standalone owner text and list markers with equal-length opaque barriers while preserving line breaks, indentation and UTF-16 offsets. Valid standalone Date values also receive barriers in declined records, preventing native cross-line association before whole-block rejection; same-line explicit date/clock events retain their meaning. These barriers prevent Chrono from consuming a sibling bullet as a range endpoint or merging a removed date into a clock. Actual clock/range detections remain authoritative; returned spans crossing a barrier are declined. Conversion distinguishes owned, blocked and ordinary legacy context, preventing structural dates and explicit sibling overrides from leaking beyond their domain. Date-only messages restore their saved ordinary date detections. Newly inherited results retain the original clock/range source span and disclose `Date from message context`; omitted owner years also disclose the assumed year and source-local reference date.

One or more leading Markdown `>` markers identify quoted lines, including empty quoted separators and nested prefixes. Quoted standalone dates receive barriers before native cross-line merging and cannot seed legacy context; quoted clocks remain detectable with reference-date fallback. A quoted event with its own explicit date and clock remains valid. Quote and fence entry/exit reset inferred legacy carry, and unquoted structural contexts stay independent. Fenced standalone dates also receive premerge barriers; fenced clocks and explicitly dated events remain detectable but cannot seed outside context. Date-only messages restore ordinary quoted date detections with original UTF-16 indices. This adds no generalized quoted-prose inference.

Within structural domains, a validated adjacent explicit zone ends the source span before activity text. The same token recognition supplies source-zone selection and the literal source envelope, including multiword US regional aliases, IANA IDs, fixed offsets and recognized abbreviations with optional `in`/`at`. A spaced activity colon after a complete validated zone ends that envelope; greedy token extraction followed by boundary validation prevents a multiword alias or offset from shortening at malformed continuations. Only validated zone/city suffixes expand the native clock core; unsupported post-zone `in the` activity cannot add a dangling connector or metadata. Complete parser-owned clock modifiers remain inside that native core. Removing parser-owned leading whitespace advances the original source index by the same amount. Parser-confirmed clock separators after plain UTC/GMT stay separate from signed-offset validation: native parsing retains single-hyphen ranges and double-hyphen independent points, while malformed signed offsets still require correction.

For owned events, an adjacent `in`/`at` city uses the longest exact offline city prefix within the existing bounded lookup, keeping ordinary activity out of the source envelope and city query. Prefix narrowing does not use typo matches. When a parser-confirmed activity barrier establishes a complete preceding city query, the existing unique-typo rule may resolve that whole query with its interpretation disclosure; corrected arbitrary prefixes remain excluded. A native dangling `in`/`at` connector is returned to the adjacent city envelope. Legacy city lookup retains its behavior.

Calendar reference provenance follows effective date components after event, owner and range resolution. Casual noon/midnight clock tags alone do not make a stated full date or inherited explicit year reference-dependent. Genuine relative calendar/instant expressions retain reference disclosure; yearless owners retain their context date, final assumed year and source-local reference date. A reference-day fallback discloses both the assumed date and reference date used.

Textual owners resolve through the existing month-first parser for both textual orders, independently of the numeric-date preference used to extract events. Each source-zone choice resolves its own reference and closest year, then checks any weekday against that date; the target zone never selects the date. Existing clock/range grammar, precision, source-zone alternatives and DST behavior remain in effect. A double hyphen does not create a range or overnight rollover.

For omitted owner years, the pinned closest-year comparison runs on a UTC surrogate of the source-local civil reference, preserving sequential month/day rollover and strict next-year/previous-year comparison without depending on the device timezone. Assumed owner-year disclosures use each endpoint's final civil year after qualified-range rollover; a stated owner year remains explicit. Ordinary legacy and directly parsed dates retain their existing year selection.

## Timezone interpretation

Explicit offsets and standard/daylight abbreviations remain fixed offsets. Regional PT/ET/CT/MT and IANA zones use event-date DST rules. Supported ambiguous abbreviations retain all labeled alternatives. Curated offline city aliases and unique bounded typo matches need no geocoder.

Temporal returns both valid instants for a repeated DST local time and a warning for a nonexistent local time. Unknown zones/cities and unsupported vague expressions require correction rather than an invented answer. See [the product contract](../planning/web-product-contract.md) for exact independent examples.

## Merge and display

Results keep their source identity, date and range endpoint. Duplicate mentions increment occurrences; an explicit source can replace an equivalent assumed source. Target changes only reformat existing results. Display and copying preserve the full date, offset/zone, seconds and milliseconds when supplied. [Merge rules](merge-philosophy.md) explain the boundaries.

Within valid structural items/Time values, complete repeated ranges collapse only when their entire ordered resolved peer inventories match: endpoints, exact instants or dates, source zones/labels, interpretations and numeric-date metadata. Corresponding peer occurrences increase together, retaining the first mention's original span, IDs, groups and disclosures. Different ranges sharing one endpoint, independent points, different precision or meaning, incomplete inventories and legacy ranges remain distinct. The converter requires every peer to belong to the same item and protects a range when any parsed source alternative loses an endpoint to a zone error or DST gap; fold alternatives do not require equal endpoint counts. The pure range helper does not mutate its inputs.

Authored clock precision travels privately from original extraction captures, independently of normalized values and certain/implied components. Endpoint descriptors distinguish hour, minute, explicit seconds and fractional digit count, including zeros and omitted endpoint fields. Equivalent clock formatting and zone whitespace do not create distinct precision. Native numeric adapters and the known military, shorthand, between and exact clock-word paths record lexical provenance before merging; inherited or uncertain clock provenance protects the whole range. The converter supplies an object-keyed precision map separately to the atomic helper, which also requires consistent precision across each endpoint's interpretation peers. No precision fields are emitted in result DTOs, and the legacy point merge remains unchanged.

## Request lifecycle and privacy

`App.tsx` creates a disposable worker for each conversion. Request IDs and invalidation prevent late results from replacing edited/cleared input. Errors retain editable text. Conversion text stays in memory; only preferences persist by default. A supported POST share or explicit update uses a short-lived, single-use local handoff.

The build bundles UI/parser/polyfill/worker/CSS/icons/notices on the same origin. Atomic service-worker preparation confirms all required assets before reporting Offline ready. New versions wait for explicit activation; partial installations retain the working cache.

Optional learned span detection is a separate research/benchmark ticket. It must justify its browser size, latency and accuracy before enhancing the deterministic path. See [ML research](../planning/lightweight-browser-ml-research.md).
